# AudioBraille v10：拼音对照的完整/不完整显示

日期：2026-08-27
状态：用户已批准设计，待实现

## 1. 目标

保留现有“盲文方序列 → 拼音”能力，同时改善不完整输入的明文对照：

- 完整、可按项目规则解析的拼音结构显示标准带调拼音。
- 不完整但能识别组成部分的输入，显示已识别的声母、韵母或正式声调名称。
- 完全无法识别的盲文方继续使用 `·` 占位。
- 不把拼音判断用于光标移动、插入、删除、输入限制或自动修复。

## 2. 非目标

本次不实现：

- 拼音音节语义分组或持久化分组。
- 普通话声母、韵母的完整合法组合表。
- 不完整输入阻止、纠错、合并或拆分。
- 按音节移动光标或按音节删除。
- 修改文档级光标模型。

编辑器仍只处理盲文方和空格；拼音解析只属于对照显示层。

## 3. 当前能力与兼容要求

现有 `dotsSeqToPinyin()` 已支持：

- 声母 + 韵母 + 声调：例如 `m + a + 阴平` → `mā`。
- 声母 + 韵母：例如 `m + a` → `ma`。
- 零声母韵母及其声调。
- g/k/h 与 i、ü 开头韵母的变读。
- 现有 e/o 共用点位的既有解析结果。

该函数保留原有完整输入行为和公开接口。未知或不完整序列的旧 `·` 行为不直接删除，以免破坏既有调用者；新增面向 UI 的格式化函数。

## 4. 对照格式化规则

新增一个拼音对照格式化函数，建议命名为 `formatPinyinReference(dotsSequence)`。它只返回显示层结果，必要时可以同时返回状态。

### 4.1 完整结构

| 盲文结构 | 显示 |
|---|---|
| 声母 + 韵母 + 声调 | 带调拼音，例如 `mā` |
| 声母 + 韵母 | 不带调拼音，例如 `ma` |
| 韵母自成音节 + 声调 | 按现有零声母规则显示，例如 `yī` |
| 韵母自成音节 | 按现有零声母规则显示 |

“完整”指当前引擎能够按声母、韵母、可选声调的结构解析，不额外验证该声母与韵母是否构成现实中的普通话音节。

### 4.2 不完整但可识别

使用正式声调名称，不使用“一声”等口语编号：

- 声母 + 声调：`m（阴平）`
- 单独声母：`m`
- 单独韵母：显示韵母值或现有零声母形式
- 单独声调：`（阴平）`

声调名称固定为：

```js
{
  '1': '阴平',
  '2': '阳平',
  '3': '上声',
  '4': '去声'
}
```

### 4.3 未知方

既不是已知声母、韵母，也不是已知声调的方显示 `·`。未知方不得被猜测成拼音。

## 5. 解析边界

格式化器按盲文方顺序读取，但不保存音节分组：

```text
m + a + 阴平 → mā
m + 阴平    → m（阴平）
m            → m
未知方       → ·
```

用户删除 `ba` 中的任意一方后，显示层只重新格式化当前序列；如果序列不再完整，就显示剩余的可识别部分，不修改用户输入。

例如：

```text
[b] [a] [阴平] → bā
删除 [a]       → b（阴平）或按剩余顺序显示对应可识别部分
```

## 6. 代码边界

- `src/braille-engine.js`
  - 保留 `dotsSeqToPinyin()`。
  - 新增对照格式化函数及声调名称常量。
- `src/notes.js`
  - 中文笔记对照改用新格式化函数。
  - 英文逐方对照和 AudioBraille 回放不变。
- `src/input.js`、文档编辑器、`app-state.js`
  - 不增加音节字段，不改变光标和删除语义。
- `storage.js`
  - 不增加新的持久化格式。

## 7. 测试验收

新增或更新测试：

1. `m + a + 阴平` 显示 `mā`。
2. `m + a` 显示 `ma`。
3. `m + 阴平` 显示 `m（阴平）`。
4. 单独 `m` 显示 `m`。
5. 单独声调显示正式名称。
6. 未知方仍显示 `·`。
7. 现有零声母、变读和 e/o 解析测试继续通过。
8. 笔记中文对照使用新结果。
9. 光标插入、删除和 AudioBraille 逐方播放行为不受影响。
